# Site-wide portfolio assistant

The persistent assistant replaces large inline chats with a shared panel and compact contextual entry points. Its role/interest lens, draft, transcript, and request state survive App Router navigation. The homepage and collections default to whole-portfolio scope; detail, profile, Method, and utility pages default to current-page scope. An unsupported route uses portfolio context instead of fabricated page grounding.

## Architecture

- `lib/portfolio-agent/catalog.ts` resolves server-owned authored contexts and creates a compact public client catalog. It includes existing canonical projects, public legacy cases, collections, About, Method chapters, Resume, Contact, and Sound Seeker. Utility pages do not enter project ranking.
- `lib/portfolio-agent/capabilities.ts` is the shared deterministic ranking, navigation validation, and DOM form-submission layer. Existing ranking and the authored creative tour retain their order.
- `PortfolioAssistantProvider` owns one restore request, bounded local session state, submissions, retry IDs, lens updates, and conversation controls. A request captures its page and scope. Replies merge into current state rather than reverting browsing signals. Navigation only executes for the active request on the unchanged browsing revision, once per turn; restoring history never executes actions.
- `PortfolioAssistantShell` supplies a docked panel at 1440px and above, a modal drawer below, and a full-width mobile sheet. The composer stays pinned. Ctrl/Cmd+K opens it outside editable controls; Escape closes it and returns focus. Modal layouts make background content inert; media dialogs retain their higher stacking order.

The existing `/api/portfolio-copilot` route still validates input, resolves canonical content server-side, reserves idempotent turns, enforces existing limits, and invokes the grounded answer service. New optional preferences are `scope: page | portfolio` and `entryPoint: ui | webmcp`. Omitted scope preserves legacy behavior. Structured navigation actions are generated by canonical lookup, never by model output. Model-written action fields are discarded.

`GET /api/portfolio-agent/evidence?slug=…` returns only authored summaries, excerpts, highlights, source links, and claim boundaries. Unknown slugs return 404. It does not query private career records, return stored conversations, or mark authored claims as independently verified. Its response is publicly cacheable for five minutes.

`PATCH /api/portfolio-copilot/conversation` accepts `{rawInput: string | null}` to update or clear an existing anonymous conversation's lens. It uses the same origin and opaque cookie boundary; it never creates a conversation. The stored lens is updated atomically without replacing unrelated memory or extending retention. A turn's explicit `visitorIntentCleared` signal prevents a failed lens PATCH from reviving old role context on the next question.

## Native WebMCP

WebMCP is a progressive enhancement using `document.modelContext`, without a polyfill or framework dependency. See the official [imperative API](https://developer.chrome.com/docs/ai/webmcp/imperative-api) and [declarative API](https://developer.chrome.com/docs/ai/webmcp/declarative-api). Browser support and the experimental contract must be verified when updating this adapter.

Always-available imperative tools in supporting browsers:

| Tool | Effect |
| --- | --- |
| `find_relevant_work({intent})` | Read-only deterministic ranking, up to five results; does not set a lens or call a model. |
| `get_page_evidence({slug})` | Read-only authored evidence projection; no conversation or private-record access. |
| `navigate_to_page({slug})` | Changes the current page using an allowlisted slug. |
| `open_portfolio_assistant({})` | Opens the visible assistant and its optional lens editor, exposing the real forms. Returns public surface metadata, not history. |

All tools use `consequentialHint: false`. Only read operations use `readOnlyHint: true`; returned tool content is curated by this site, so `untrustedContentHint: false`. Abort signals unregister the tools on unmount and cancel supported asynchronous operations. Stale registration handles reject execution.

When the panel is open, its composer is a real `ask_portfolio_guide` annotated form. Opening the lens editor exposes `guide_portfolio_tour`. Closing/removing a form removes that tool; there are no duplicate imperative tools with these names and no invisible proxy forms. Form attributes include `toolname`, `tooldescription`, `toolparamdescription`, and the presence attribute `toolautosubmit`. Both forms read FormData rather than trusting React-controlled state. The native agent submit event receives its result promise synchronously through `respondWith()` after `preventDefault()`. The composer description and visible notice disclose OpenAI processing and 90-day conversation retention. Native cancellation of a question aborts the client request.

Contact messages, resume generation/delivery, and creative-demo controls are not exposed. Navigation can open their existing pages; it cannot submit their forms.

## Rollout and verification

See the [native WebMCP and retrieval follow-up](./portfolio-assistant-validation-2026-10-17.md) for current runtime results, and the [original implementation validation record](./portfolio-assistant-validation.md) for earlier checks and screenshots.

- `NEXT_PUBLIC_PORTFOLIO_ASSISTANT_ENABLED=false` restores the original inline guide and homepage role form. The two legacy client components are retained for rollback.
- `NEXT_PUBLIC_PORTFOLIO_WEBMCP_ENABLED=false` disables native tool registration and form annotations while keeping the human UI.
- `NEXT_PUBLIC_WEBMCP_ORIGIN_TRIAL_TOKEN` optionally supplies a public origin-trial meta token. Configure it for the actual deployed HTTPS origin; a token is not included in this repository.
- Ordinary browsers require no flags. For native testing in supporting Chrome, use `chrome://flags/#enable-webmcp-testing` and the Model Context Tool Inspector. Browser agents must visit the site to discover its tools.

Run `npm run test:portfolio-guide`, `npm run typecheck`, `npm run lint`, and `npm run build`. Start with the inference-free `eval:portfolio-guide` checks. After meaningful AI behavior changes, generate only affected local cases (smoke for shared changes), reuse cached answers, and review frozen packets in the active Codex chat. Local judges are explicit advisory diagnostics; full suites and live dependencies remain explicit. New cases with IDs beginning `site-` cover homepage discovery, collections, creative status, About, Method, essays, and private-alpha boundaries. The browser journey should also verify annotations and submission behavior, page attribution across navigation, draft preservation, lens clearing, focus restoration, responsive layouts, retry/cancellation, and storage outages.

## October 21 release extraction

This branch extracts the site-wide UI/native adapter onto the current bounded claim-ID selector and qualified renderer. It includes reviewed evaluation/qualification branches, but no semantic indexes, new relevance call, free-prose service or private career record. Whole-portfolio scope supplies up to three deterministic public project contexts; page scope supplies the server-owned public page. Site/About/Method paragraphs become complete qualified source blocks. Model-authored actions are never executed; navigation is canonical lookup only.

Both public feature flags now default **off** and require exact `true`. With assistant off, the existing inline components and canonical API page catalog remain active. Human UI and native annotations are separate opt-ins; public flags require rebuild/redeploy. Existing feedback remains visible above the launcher. No production flags changed. No new database schema is introduced; existing conversation storage remains a separate deployment dependency. The public evidence GET exposes authored public material, not private profiles or stored conversations.

Search PR #13 remains a separate draft with a paid embedding gate. Merge integration of the service/http/types adapters must preserve its qualified blocks and guards; this branch does not claim semantic readiness. Browser checks use a locally built site, mocked conversation/answer responses, blocked external traffic and no provider/database credentials. Native availability must be reported separately from synthetic lifecycle tests. No origin-trial token is supplied.
