## Diagnosis

All four paid candidate responses satisfied their then-current ID schema. The catalog was not too large for the API: the page cases offered four or five IDs. The problem was semantic granularity. One ownership block contained seven or more sentences, the two-ID limit imposed no prose budget, and overlapping blocks repeated qualifications. The 15-ID across-portfolio catalog allowed two current-page blocks and required no supporting project. The renderer did not name the supplied role. Catalog-size reduction is a design correction, not evidence about what caused a model's internal choice.

Ownership, AI assistance, no-sole-coding, implemented resume jobs, disabled remote retrieval and pending local-release status stay together.

The obsolete broad definitions for the replacement blocks were removed. Untargeted generic page blocks retain their existing behavior; this is a bounded correction rather than a claim that every portfolio question is now concise.
